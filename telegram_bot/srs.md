### Уточнения (команды, архитектура, индексация, ошибки, тесты)
 
 - Команды бота:
  - `/list [--all|--aliases] [--q "<filter>"]` — показать список доступных агентов. Вывод: по одному имени на строку в формате `@Name`. С `--aliases` добавлять алиасы; каждая строка алиаса начинается с двух пробелов перед `@` (например, `␠␠@Alias`). С `--q` — фильтровать по подстроке.
  - `/call [--echo] @Name <input>` — запустить агента по имени или алиасу (регистр не важен). Ввод `<input>` передаётся в lib без изменений. Также распознаются текстовые формы без слеша: `list`, `@Name <input>` и `call [--echo] @Name <input>`. Флаг `--echo` прокидывается в lib/cli для возврата расширенных метаданных/эхо.
 
 - Архитектура и разделение на lib/cli:
   - В lib определить публичные функции:
     - `call(name: str, input: str, *, chat_id: int | None = None, thread_id: int | None = None) -> str | None` — запускает пайплайн и возвращает, например, URL публикации/идентификатор запуска.
     - `list(query: str | None = None, include_aliases: bool = False) -> list[dict]` — возвращает список агентов с алиасами и краткими описаниями (если есть в индексах).
 
 - Индексация и поиск агентов:
   - Реализовать стратегию «сначала индексы, затем сканирование» на основе `call/app/call.py`:
     - Сначала читать `AgentFab/agents.yaml`, затем `agents/agents.yaml` (учитывая секции `agents` и `aliases`).
     - Использовать нормализацию имени, аналогичную `to_pascal_case()`.
     - Фоллбэк: поиск `agent.yaml` в `AgentFab/<Name>/` и `agents/<Name>/` (без учёта регистра).
   - В выдаче `/list` показывать по одному имени на строку в формате `@Name`. При `--aliases` — после `@Name` выводить алиасы, каждый с двумя пробелами перед `@` (например, `␠␠@Alias`).
 
 - Обработка ошибок и UX:
   - При неизвестном агенте — предлагать ближайшие совпадения из индекса (fuzzy/startswith).
   - Ограничивать размер `<input>` (например, до 8‑16К символов) с понятной ошибкой.
   - Для длинных ответов — публиковать через lib (Telegraph) и присылать ссылку.
   - Логи: писать в `call/logs/` и в консоль; критичные ошибки возвращать в чат в сжатом виде.
 
 - Параллельная работа и отмена:
   - Одновременные запуски в разных чатах/тредах не должны конфликтовать (раздельный контекст).
   - (Опционально) Добавить `/cancel` для прерывания своей задачи, если lib поддержит.
 
 - Тестирование:
   - Юнит‑тесты: парсинг команд (`/list`, `/call`), валидация входа, авторизация `ALLOWED_USERS`, интеграция с DI‑заглушкой lib.
   - Интеграционные тесты: happy‑path `/call @Name ...` с мок‑lib; `/list` с разными флагами; неизвестный агент; ошибка lib.
   - Покрыть индексацию и алиасы (см. тесты `call/app/tests/test_discovery.py`).
